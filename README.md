# Comps Scrubber

A Python tool that reads SEC filings and produces **comparable-company analysis with an audit
trail**. It pulls reported financials from XBRL, finds non-recurring items (restructuring,
impairments, litigation, M&A costs, asset-sale gains/losses, stock-based compensation) by reading
each company's 10-K and 8-K Exhibit 99.1, and builds a reported → adjusted EBITDA bridge where
every adjustment is quoted verbatim from the filing and verified by code.

## Why this exists

Reported EBITDA includes one-off items that make peers non-comparable. Analysts "scrub" each peer
by hand. This tool does it consistently: one shared adjustment policy is applied to every peer,
and no number is generated by the LLM without being checked against the source text (and, where a
us-gaap tag exists, against XBRL).

## How it works (pipeline)

1. **Resolve** ticker → CIK → 10-K filings (edgartools).
2. **Pull structured financials** per fiscal year from the SEC companyfacts XBRL API
   (revenue, operating income, D&A, net income, total debt, cash, share count).
3. **Retrieve source text**: the 10-K and the 8-K Exhibit 99.1 earnings release.
4. **Extract** candidate adjustments + the company's own reported adjusted EBITDA via
   OpenAI structured output.
5. **Verify** every amount by code: (a) the quoted sentence must appear verbatim in the filing,
   (b) the amount must be recoverable from the digits + scale in that quote, (c) where a us-gaap
   tag exists, the amount is cross-checked against XBRL, (d) the bridge must foot.
6. **Apply policy** to normalize items into one category schema across peers.
7. **Value**: EV = market cap (price × shares) + debt − cash; EV/Revenue, EV/EBITDA (reported +
   adjusted), P/E; mean + median.
8. **Write** the Excel workbook.

## Setup

```bash
cd comps-scrubber
python -m pip install -r requirements.txt
copy .env.example .env    # Windows; use `cp .env.example .env` on macOS/Linux
```

Then pick an LLM provider in `.env`:

**Option A — ChatGPT account (no API key).** Install and sign in to the
[Codex CLI](https://developers.openai.com/codex/) with your ChatGPT account (`codex login`), then
set `LLM_PROVIDER=codex` (or leave it `auto`). The tool locates the Codex binary from
`CODEX_CLI_PATH`, `~/.codex/config.toml`, or your `PATH`, and uses Codex's structured-output mode
(`--output-schema`) so every extraction returns schema-conformant JSON.

**Option B — OpenAI platform API key.** Set `LLM_PROVIDER=openai` and fill in `OPENAI_API_KEY`
(the key is used only for the extraction/classification step).

`.env` is gitignored and never committed. The `LLM_PROVIDER` value you choose locally is not
part of the repo — other users pick whichever option fits them.

## Run

Demo (8 software peers × 3 fiscal years, from `config/peers.yaml`):

```bash
python demo/run_demo.py
```

This writes `output/comps_output.xlsx` and `demo/writeup.md` (a comparison of the tool's adjusted
EBITDA vs each company's own reported adjusted EBITDA).

Custom run:

```bash
python cli.py --peers config/peers.yaml --policy config/policy.yaml --output output/my_comps.xlsx
```

## Configuration

**`config/peers.yaml`** — tickers and number of fiscal years:

```yaml
peers: [MSFT, ORCL, CRM, ADBE, NOW, INTU, SNOW, WDAY]
num_years: 3
```

**`config/policy.yaml`** — the shared adjustment policy. Toggle categories and their treatment
(`add_back` = add an expense back; `subtract` = remove a gain; `auto` = add back losses / subtract
gains). By default stock-based compensation is **not** added back (it is recurring); flip it to
`true` to match most software companies' non-GAAP EBITDA.

## Output workbook

- **`Comps`** — one row per peer × fiscal year: reported vs adjusted EBITDA, revenue, net income,
  debt, cash, market cap, EV, and EV/Revenue, EV/EBITDA (reported & adjusted), P/E — with mean and
  median rows.
- **`Bridge - <TICKER>`** (one per company) — reported → adjusted EBITDA; each adjustment row shows
  its amount, category, the verbatim source quote, the section name, and a one-click hyperlink to
  the exact SEC filing (10-K or 99.1).
- **`Flags`** — items needing human judgement: recurring restructuring, unverifiable quotes, XBRL
  mismatches, missing 99.1 releases.

## Notes / limitations

- **SBC** is the main systematic difference vs company non-GAAP (see the demo write-up).
- **Total debt** is `DebtLongtermAndShorttermCombinedAmount` when the company tags it, otherwise
  the sum of long-term debt + short-term borrowings + notes payable + commercial paper +
  convertible notes. Unusual debt structures are worth a human glance.
- **Section links** point to the filing document URL (with the section name + quote in the cell),
  since not all filings expose stable per-section anchors.
- First run downloads filings (cached in `cache/`); re-runs are fast.
